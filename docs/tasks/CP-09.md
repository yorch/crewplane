## Scope

### 1. Per-lane guidance (gap 1)

Add optional `lanes.<id>.instructionsPath`: a safe relative project path, no traversal/absolute/control characters, existing file under the primary project root at configuration time, maximum 32 KiB. It augments the global `instructionsPath` from `crewplane.json`. Tool-capable harnesses are told to read it in their checkout; content is not injected. The global path remains the default policy for every lane.

### 2. No-tools harness context (gap 2)

Pi is `--no-tools --no-context-files`, so it cannot read files, use the board or inspect a SHA. The supervisor prompt is the only input. For `nativeTools: "disabled"` adapters, build the prompt asynchronously with bounded inline context: global instructions, lane instructions and the committed task card (when a task exists), each clearly delimited, total ≤ 32 KiB, and without board-operation instructions. If a declared file is missing or over the inline bound, pause the turn with a precise reason instead of sending a prompt that tells the agent to read unavailable files. Findings remain in the bounded `summary` because the result schema is unchanged.

### 3. Permission denials and mode policy (gap 3)

Claude `result.permission_denials` is counted into a new stream/record field. A `ready` result with one or more denials pauses for operator inspection with a precise reason; non-ready states keep the count visible without changing disposition. There is no hardcoded role/mode matrix: local probes show `plan` and `dontAsk` can still execute `Bash` when Claude settings allow it, so mode behavior is host-dependent. Configuration validation requires explicit modes and rejects bypass/manual as before, and `doctor` continues to report the configured mode.

### 4. Audited new session (gap 4)

Extend the queued `retry` control with `--new-session true` and a required note. When applied, it clears the record's native session identity so the next turn starts fresh, records `sessionResetAt`, and leaves the lane's configured `sessionEpoch` untouched. It must not run while the record owns a live or unverified process, and it never lifts an operator hold. Other retry semantics (failure recovery, cleanup acknowledgement) are unchanged.

### 5. Harness isolation options (gap 5)

Claude lane options:

- `claudeMcp`: `"strict"` (default) or `"inherit"` → `--strict-mcp-config` when strict.
- `claudeSettingSources`: default `["project"]`; explicit subset of `user`, `project`, `local` → `--setting-sources`.
- `claudeTools`: optional availability allowlist → `--tools` (least privilege; must include `Bash` because every lane needs the board CLI).
- `claudeAllowedTools` and `claudeDisallowedTools`: optional approval/deny lists → `--allowedTools`, `--disallowedTools`.

OpenCode lane options: `opencodeAgent` → `--agent <name>`. Crewplane does not claim to disable OpenCode config, plugins or MCP servers; the trust boundary is documented, and an invalid agent fails closed through the native `error` event.

### 6. Per-lane budgets and reported cost (gap 6)

Add optional per-lane `maxRunsPerHour` and `maxRunMinutes` (integer 1–60), falling back to the global values in scheduling and the run deadline. Add optional `maxCostUsd` for Claude only: a finite number > 0 and ≤ 100, passed as `--max-budget-usd`; Claude's `error_max_budget_usd` result pauses with a precise reason. Record reported cost (`total_cost_usd` cumulative for Claude, per-step sum for OpenCode) in the record and read model as observed metadata, never as billing. Reject `maxCostUsd` for harnesses without a native cap.

## Design review revisions

An adversarial Opus design review rejected the first draft. Adopted corrections:

- **Prompt before launch mutations.** Build and bound the prompt (context reads, adapter lookup, notices) before charging a run, deleting notices, creating traces or spawning. A failure uses the full-record failure pause and loses nothing.
- **No-tools lanes are reviewer-only.** Reject no-tools harnesses on coordinator and implementer lanes. Their prompt is harness-neutral: no board/read-file instructions; global/lane instructions and the pinned task card are JSON-encoded inline data. After a valid turn the record is paused as a decision, its triggering events and message watermarks are consumed, and the summary is surfaced for operator relay; it never claims board completion and never relaunches on the same event.
- **Denied ready is not completion.** A task-owning turn returning `ready` with a known non-zero denial count pauses as a failure, writes no `finalState` and does not advance seen/message evidence. Coordinator (`task: null`) turns record denials without pausing. Pauses caused by denials or budget remain failures even when the lane is held.
- **New session is single-target and atomic.** `retry --new-session true` requires `--task`, a note and a single matching non-running record with matching harness/epoch and no live/unverified process. It refuses `--confirm-cleanup`, performs every check before any mutation, keeps holds, and persists an applied/refused outcome plus a bounded previous-session audit record.
- **File checks move out of `validateConfig`.** `validateConfig` only validates path shape; existence, containment, regular-file and size checks run in `configure`, `doctor` and at prompt build so pause/retry/status never throw. Reads resolve real paths under the primary root, reject private-store segments, and are byte-bounded. Task cards are read from the pinned `baseCommit` via `git show`, not the working tree.
- **Isolation is explicit.** Claude requires `claudeMcp` and `claudeSettingSources`; `project` settings are documented as agent-writable, not least privilege. `claudeTools` is availability and must include `Bash`; allowed/denied lists use separate grammars, are comma-joined, and cannot blanket-deny `Bash`.
- **Budgets tighten only.** Per-lane run-rate and timeout overrides must be ≤ the global values. The cost cap is renamed `maxCostUsdPerRun`, is Claude-only, and is documented as per-invocation with possible overshoot. Reported cost is per invocation with a known flag and finite bounds; observed evidence shows Claude `total_cost_usd` does not accumulate across resume.
- **Unknown lane keys are rejected**, and new optional record fields are validated for old-state compatibility.

Allowed paths additionally include `src/engine/dashboard/headless.ts`, `src/engine/dashboard/headless.test.ts`, `src/engine/scheduling.ts` and `src/engine/scheduling.test.ts` if read-model/budget plumbing requires them.

## Code review corrections

A second adversarial Opus review found two high and eight medium defects. Corrections applied: ambiguous `--new-session` records are refused instead of resetting the oldest match; queued notices are byte-bounded for the prompt so one oversized note cannot wedge a lane; no-tools prompts now carry the pinned review target and omit board/thread instructions; blanket `Bash`/`Bash(*)` denial and unparenthesized deny rules are rejected; resolved instruction paths are re-checked for private-store segments (including symlinks and case-insensitive names); instruction reads are byte-bounded from one descriptor; oversized global guidance pauses a no-tools turn but remains soft for tool-capable lanes; the pinned-card size limit applies only when inlining; non-string OpenCode agents are rejected; lane-wide unverified cleanup is checked before reset; prior denial/cost values are cleared at launch; and `lastSessionReset: null` validates as invalid.

Documented residual limits: a denied `ready` pauses the lane but cannot retract a board `ready` already published; advisory decision pauses require explicit operator retry and leave the request thread unanswered; global guidance remains soft-failing when absent (oversize is hard for no-tools); and supervisor acceptance tests for denied-ready, budget pauses and per-lane timeouts remain a follow-up (stream, control and advisory paths are covered).
