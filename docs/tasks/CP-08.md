## Scope

Add two harness adapters, `claude` (Claude Code 2.1.319 probed locally) and `opencode` (OpenCode 2.2.5 probed locally), without changing the Codex or no-tools Pi protocols.

- Claude invocation: `-p --output-format stream-json --verbose --json-schema <inline schema> --add-dir <project root> --model <explicit model> --permission-mode <explicit non-bypass mode>`, fresh runs pinned with a generated `--session-id` UUID and later runs resumed with `--resume`.
- OpenCode invocation: `run --standalone --format json -m <provider/model>` with optional explicit `--auto` and `--session` resume. The harness generates a `ses_…` identity on a fresh run; Crewplane resumes it rather than inventing one.
- Native results: Claude supplies `structured_output` from its `result` event; OpenCode receives a prompted JSON-only answer because its JSON stream has no schema-enforced result. Missing results, error events and session/cwd contradictions fail closed.
- Capability matrix is explicit: resume, native vs prompted structured result, tool policy, observed model, observed cwd, partial usage. Unknown dimensions stay unknown.
- Session identity is harness-specific: UUID for Codex/Pi/Claude, `ses_` prefixed for OpenCode. Cross-harness, cross-epoch and malformed identities remain rejected.
- Operational traces, the dashboard harness filter and the usage-ledger harness allowlist learn the new harnesses; no raw payloads, reasoning, credentials or provider traffic are stored.

## Boundaries

Live provider compatibility is evidence from local CLI invocations, not certification across versions, credentials, networks, Windows or long-running supervision. No OpenCode model observation or cwd observation exists in its JSON stream; the dashboard must not invent one. `--dangerously-skip-permissions`/`bypassPermissions` and manual permission prompts remain unavailable. OpenCode `--auto` is opt-in and never default.

OpenCode `--session` also creates an absent session, so resume cannot be distinguished from a silent empty restart; it is documented as best-effort identity continuity, not exact context restoration. The CP-06 synchronous-spawn lifecycle case is adapted: a NUL-contaminated model is now rejected before ownership, state or trace creation instead of reaching spawn, which is the stronger fail-closed invariant; the synchronous spawn branch remains as defense-in-depth. Reported token counters are harness fields, not billing totals: Claude `input_tokens` excludes cache creation/read, OpenCode reports cache/reasoning separately. Compiled-executable acceptance still runs its full synthetic workflow through the Codex fixture; Claude/OpenCode coverage is source-level stream, argv, trace and real-process lifecycle fixture evidence plus local CLI protocol probes. Extending the compiled acceptance fixture to every adapter remains a follow-up.
