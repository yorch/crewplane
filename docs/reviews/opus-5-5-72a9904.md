## Remaining fixes

### F1. [P2, regression from R11] A stale acceptance test blocks `verify`

- **Scenario:** `acceptance.test.ts:115-118` creates `board-mutation.lock` as a directory and expects "Board mutation busy". That string no longer exists in production code.
- **Trace:** `writeFile` gets `EEXIST`, and `owner()` rejects the non-file (`process-lock.ts:17-23`). The loop then reaches its 10-second deadline and throws "Process lock unavailable" (`:105-106`).
- **Effect:** the test is in the Vitest include set, runs within the 30-second timeout, and is reached by CI through `verify.yml:36`.
- **Fix:** write a mode `0600` lock file holding `{pid: process.pid, token: <uuid>}`, and expect "Process lock unavailable". Update the now-dead retry at `tests/fixtures/harness.ts:17` as well.

### F2. [P2, residual of R2] An unclaimed sibling can still pause its lane

1. Lane `builder` has A and B `ready`, and C assigned but unclaimed. A correction takes B to `working`, then `blocked`, and the lane has no unanswered outbound question.
2. C still gets an `implementation` candidate. The `competing` check applies only to frozen tasks (`orchestration.ts:359-412`), and the scheduler's hold applies only while a ready correction is pending (`fair-scheduler.ts:310-329`).
3. C's agent runs `claim`, which the guard refuses (`agents.mjs:793,336-343`).
4. With no progress, the count rises (`wait-policy.ts:77-83`) and C retries after 15 seconds (`orchestration.ts:166-176`). The second turn pauses it (`supervisor.ts:1002-1003`).
5. `failurePaused` then blocks the lane's other work too (`orchestration.ts:518-523`). An operator `retry` restarts the cycle while B stays non-ready.

The same happens when A's correction spans several turns. If the lane has an unanswered question and C returns `waiting`, only one turn is wasted (`supervisor.ts:949-953`).

- **Fix:** do not offer an unclaimed task while its claim would be refused. For example, set `ownershipValid = false` when no claim or status exists and any same-lane active sibling is not `ready`.
- **Regression:** extend `orchestration.test.ts:789` so C gets no work while B is blocked and while A is mid-correction.

### F3. [P3, residual of R6] Coordinator triage cannot close a peer question

1. B, with an active task T, asks idle lane C a direct question with `--task T`. The coordinator is notified, but C correctly gets no turn.
2. The coordinator cannot reply on that thread, because the parent must be addressed to it (`agents.mjs:530-533`).
3. It can send a task decision with no `replyTo` (`:543-547`), which resumes B once (`orchestration.ts:329`).
4. The question stays unanswered, because answered status comes only from `replyTo` (`agents.mjs:440-442`).
5. If B's turn ends with T still `working`, `outboundWait` suppresses continuation (`orchestration.ts:153-176`). No new event or queue row appears, so B stalls silently.

- **Fix:** let the coordinator reply to an active-task peer question (`agents.mjs:530-533`), and accept that sender at `orchestration.ts:336`.
- **Regression:** after triage, the question is closed and B continues across turns.

### F4. [P3, regressions from R11 and R13] An unnormalized `CREWPLANE_COORD_DIR` breaks the CLI

`USAGE.md:9` documents this as any absolute shared store, but `project.ts:156-158` uses the value as given.

- **Trailing slash** (`/shared/store/`): the prefix test in `put` fails (`agents.mjs:39-43`), so the root becomes the Git common directory. `durableMkdir` then throws "Directory outside durability root" (`io.ts:34-37`) during `prepare`, so every CLI command fails.
- **Symlinked ancestor** (such as `/tmp/...` on macOS): `init` and `board` work, but every mutating `agents` command throws "Unsafe lock ancestor" (`process-lock.ts:54-63`). Supervised turns can then neither claim nor report status.
- **Fix:** normalize with `resolve()` at discovery. Then either canonicalize the store with `realpath` once it exists, or reject symlinked stores at discovery with a clear error.
- **Regression:** existing fixtures avoid both cases by clearing the variable or using `realpathSync`. Add both path shapes to `agents.test.ts`.
