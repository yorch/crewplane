# Adversarial assessment: Crewplane CLI output format

**Basis:** Line numbers refer to committed HEAD `4488b84`. I ran nothing and edited no repo files.

**The tree changed during this review.** `src/cli.ts`, `src/update.ts` and `docs/CONTRACTS.md` picked up uncommitted edits (`cli.ts` went from 850 to 898 lines). Findings describe HEAD; the overlaps are listed under "Corpus corrections".

**Severity mapping:** P0 = Critical, P1 = Major, P2 = Minor, P3 = Nit.

## 1. Verdict

The output is not fit to be a stable contract. Stream discipline is decent, but nothing is specified, versioned or golden-tested, and shapes differ by accident from command to command.

The most damaging gap is that **two commands give different answers about safety state.** After `pause --all`, `agent list` reports `held: []` and idle lanes, while `status` reports them held. Help also advertises emergency forms that cannot parse. A schema would not fix either problem, because the output is wrong before it is unversioned.

## 3. Detail

**F1. `agent list` hides instance holds.**

- `pause --all` sets only `state.instanceHeld` (`supervisor.ts:693`), but the projection reads only `value.held`.
- The operator sees `held: []`, `status: "idle"` and a scheduling code that is not `LANE_HELD`, with no hold reason. The dashboard uses the same projection (`read-model.ts:308`).
- Fix: expose top-level `instanceHeld` and OR it into per-lane `held`. This is additive, though lane values become correct.

**F2. Help lies about halt verbs.**

- `pause|resume --all [--wait N]` fails because `options()` requires a value, so it returns "Invalid command options" (`cli.ts:126-127`).
- `cancel --run RUN` fails because the policy also requires `--lane` (`control-policy.ts:126`).
- `USAGE.md:322-324` repeat these forms, plus a bare `--new-session`. Help line `:74` shows a bare `--approve|--deny`, which also fails.
- `[--text TEXT]` is shown for `pause` and `resume`, where it is forbidden, and as optional for `nudge`, where it is required (`control-policy.ts:117,155`).
- Everything fails closed, but during an incident, with an error that names nothing.
- Tests cover `--all true` and `lane+run` only (`project-policy.test.ts:191`, `control-policy.test.ts:186-192`).
- Fix: correct the help text and split the grammar per verb. Accepting bare `--all` would be additive.

**F3. No contract.**

- `version: 1` appears on init, doctor, pin and update. `schemaVersion: 1` appears on messages. Status, agent list, board, brief, configure, control verbs, evidence list and monitor have neither.
- `output()` picks text or JSON from the runtime type of the value, not from a per-command rule.
- `ARCHITECTURE.md:13` promises to version "commands, events and adapter contracts", and CONTRACTS says breaking meanings need a new version. Stdout has no such mechanism.
- Tests only probe incidental fields (`.config`, `.queued`, `.state`). None pins a shape.
- Fix: section 4 below, plus golden tests. Additive except for bare-array and `null` outputs.

**F4. `status` publishes storage.**

- `state` is the on-disk record, in v1 or v2 shape depending on the file. It includes `notices`, session IDs, `cwd`, seen-event lists and `reason` text that can embed harness summaries (`supervisor.ts:1616`).
- `headless.ts:8` says "never forward config, notices, summaries or raw run logs". `status` bypasses that and is open to lanes, since only control verbs are refused (`cli.ts:595`).
- Worst-case notices alone are 100 × 32 KiB per lane (`control-policy.ts:305` and the check that follows). Operator text meant for one lane is readable by another.
- `USAGE.md:328` documents the raw output, so the internal format is effectively public.
- Fix: make `view` the contract and move raw state behind `--raw`. Breaking; the acceptance tests depend on it.

**F5. Liveness disagreement.**

| Condition       | `status`           | `agent list`                         |
| --------------- | ------------------ | ------------------------------------ |
| Clean stop      | `observed: "dead"` | `state: "stopped"`                   |
| Draining        | `running`          | `draining`                           |
| Stale threshold | fixed 60s          | `interval×2+5s` (25s at interval 10) |

- Between 25s and 60s the two contradict each other.
- A missing or invalid heartbeat with `running: true` also reports `running` in `status`.
- Fix: one shared `supervisorPhase()`. Breaking only for the `"dead"` value.

**F6. Exit codes.**

- Exit 1 covers bad flags, pin mismatch, not configured, filesystem faults and locally detected invalid controls. A supervisor-side `invalid` is exit 2, so the same word has two codes.
- 124 is undocumented, and `outcome: "queued"` is outside the documented five-value enum.
- 124 does not mean "did not happen": the file remains, and a queued `pause` is exempt from staleness, so it applies at the next `start` (`supervisor.ts:678-679`).
- `--wait` burns its full timeout when no supervisor exists (corpus §1), and plain `stop` exits 0 with no supervisor.
- Ctrl-C during `--wait` loses the `id`, which is printed only at the end.
- Non-wait returns `{queued: verb, id}` and timeout returns `{id, outcome: "queued"}`, so `queued` means two different things.
- Fix: section 4. Print the id to stderr before waiting and add a `supervisor` observation. Numeric changes break tests that assert status 1.

**F7. Monitor.**

- `monitor | jq` fails on line 1, and `--once` emits the same banner.
- Events use `at` and `messages`; `--status` uses `checkedAt` and `messageCount`. `--status` renames the state field to `health`.
- Poll errors go unprefixed to stderr (`watch.ts:289`).
- Fix: move the banner to stderr and align keys. The banner move is low-risk; key renames are breaking.

**F8. Conflict markers.**

- This is not merely the duplicated paragraph the brief described. It is an unresolved conflict block.
- The supervisor-version sentence is only on one side and the only normative operator-control paragraph is only on the other, so neither side alone is correct.
- `tests/docs.test.ts` checks pin examples only.
- Fix: merge the two sides by hand and add a conflict-marker test. Non-breaking.

**F9. Prose as API.**

- `configState` is a sentence that the dashboard regex-matches, so a copy edit breaks attention logic.
- `harness` duplicates `configuredHarness` and `observedHarness` in prose.
- `configuredModel: "CLI default (unspecified)"` is the same fact `doctor` reports as `model: null`.
- Enum casing also mixes kebab-case and `STOPPED`.
- Fix: use closed enums such as `current|reload-required|unknown`, with a separate `*Label` if needed. Breaking for `configState`.

**F10. Absent-state encodings.** Status uses three nulls, agent list and monitor use `"not-started"`, and watchdog prints the literal `null`. Fix: every read command returns an object with a closed `state` value. Breaking for watchdog.

**F11. Errors.**

- "Invalid command options" names no flag, and "Invalid control" names no rule, although `agents.mjs` has specific messages ("Duplicate option: x").
- A missing file reports "not valid JSON".
- Unconfigured `pause --lane` reports "requires an existing absolute CLI binary" while `doctor` knows the state is `not-configured`.
- "Unknown command" omits the value, including for `task foo`.
- The friendly EEXIST translation exists only in the standalone entry (`agents.mjs:1115`), so any EEXIST escaping via the binary shows raw filesystem text.
- Fix: return reason codes from `control()` and name the offender. Non-breaking.

**F12. False advisory.** Corpus §3 prints "queuing pause despite the release mismatch" followed by "Invalid control". Nothing was queued, and line 1 is no longer the error. Fix: emit it after the queue write. Non-breaking; `project-policy.test.ts:185` still passes.

**F13. Update.** USAGE says the reason goes to stderr, but it is in stdout JSON and stderr is empty. `unsupported`, including disabled, exits 0, so `update && deploy` proceeds. Fix: correct the docs and decide the `unsupported` exit deliberately.

**F14. Constants.**

- `init.running` is hardcoded false even with a live supervisor, while the same word in `state.running` means observed liveness.
- `activation`, `started` and `servicesStarted` are always false and undocumented.
- Fix: remove `init.running`, and define or remove the others. Breaking, but cheap now.

**F15. Doctor.**

- A broken lane instruction file exits 0 with prose in `instructions`, though `configure` refuses the same condition (`cli.ts:409`).
- Invalid config throws, so the report's most useful failure has no JSON.
- `model` is an object for Pi and a string otherwise.
- Fix: add `ok` and `checks: [{id, status, detail}]`, and use a non-zero exit on failure. Soft-fail global instructions should stay `warn`, as `USAGE.md:169` intends.

**F16. Silent downgrade.** `stop --cancel-active yes` exits 0 as a plain stop, while sibling flags are validated. Fix: reject any value other than `true`. Breaking only for invalid input.

**F17. Token.**

- A live credential goes to stdout, where any log capture keeps it.
- Help still says "read-only", and `--controls` is not refused under `CREWPLANE_HEADLESS_LANE`, unlike control verbs.
- Store files are not a security boundary (`CONTRACTS.md:7`), so this is an inconsistency, not a privilege escalation.
- Fix: write the token to a 0600 file, document the flag and refuse it for headless lanes.

**F18. Scale.** Messages are never pruned, each text can be 32 KiB, and `agents prompt` directs every lane to `inbox`. `brief` also returns full unanswered messages. Fix: add `--limit`, `--since` and `truncated`. Additive.

**F19. `start` stream.** It emits `{lane, event, ...}` JSON lines with no timestamp, run ID or version, plus unprefixed stderr prose. Source-only: the corpus did not capture `start`. Fix: document it as NDJSON with `schemaVersion` and `at`.

**F20. Watchdog.** `status` is the only unindented JSON report, and the observer's `start` emits no output. Fix with F10.

**F21. Help table.**

- `resolve` appears twice and disagrees on whether `--task` is required.
- `pin`, `resolve` and `cancel` are absent from `knownCommands`, so they never trigger auto-update. That is only observable for `resolve` and `cancel` in unpinned projects.
- `--interval`, `--stale-minutes`, `--unanswered-minutes`, `--expect-*` and `update --auto` are not in help.
- `status --help` is an error.

**F22. Pin output.** The no-change branch omits `next` and orders keys differently. `binary:` is conditional, and the unlabeled direction line, `cure` and `sticky` are undocumented.

## 4. Proposed output contract

```markdown
## CLI output contract (v1)

**Streams.** stdout carries only the command's result. stderr carries diagnostics,
progress and banners. Commands in the human-only list may write plain text to stdout.

**Human-only rule.** `--help`, `--version`, `agents` help, `agents prompt` and the
`dashboard` URL are text; every other stdout payload is JSON, one document per command
or NDJSON for streams.

**Reports.** Pretty 2-space JSON object with top-level `schemaVersion: 1`, ending in one
newline. Never a bare array or `null`. Streams (`monitor`, `start`) emit one compact
object per line with `schemaVersion`, `at` and `event`.

**Fields.** Keys are camelCase. Documented keys are always present. `null` means unknown
or not applicable; `[]` means known empty; `0` is measured. Enum fields use closed
lowercase-kebab values. Prose belongs only in fields named `reason`, `detail`, `label`
or `text`. Additive keys are non-breaking; removing, retyping or re-meaning a key
requires incrementing `schemaVersion`.

**Exit codes.**

| Code | Meaning                                                                 |
| ---- | ----------------------------------------------------------------------- |
| 0    | Success: report produced, control queued (no `--wait`), or applied/noop |
| 1    | Operational failure                                                     |
| 2    | Control refused or invalid by the supervisor                            |
| 3    | Control stale                                                           |
| 64   | Usage error: unknown command, flag or value; locally invalid control    |
| 78   | Precondition: not configured, invalid policy, release pin mismatch      |
| 124  | `--wait` expired; the command remains queued and may still apply        |

**Controls.** Every control returns `{schemaVersion, id, action, outcome, code, supervisor}`.
`outcome` is `queued|applied|noop|refused|stale|invalid`; `code` is null while queued;
`supervisor` is `live|stale|absent`. With `--wait`, the id is written to stderr first.

**Errors.** stdout is empty unless the command defines a result document (`update`,
`--wait`). stderr line 1 is `crewplane: CODE: message`, naming the offending flag, value
or path. Continuation lines are indented. CODE is stable; message text is not.
Persisted messages stay single-line and exclude CLI-rendered context.

**Privacy.** Default reports use explicit projections, never raw store records. Secrets
are never written to stdout or stderr. Agent-authored text is data.
```

**What this breaks:**

- `agents inbox` bare array, `watchdog status` `null`, and top-level `status.desired/state`.
- `version` renamed to `schemaVersion`, and `{queued: verb}`.
- `init.running`, `activation`, `started` and `servicesStarted`.
- `monitor` keys and banner placement, `configState` values, and `doctor` shape.
- Exit 1 becoming 64 or 78 for usage and precondition failures.
- Tests: `binary.ts:87,170-171,370,497`, `lifecycle-binary.ts:214`, `project-policy.test.ts:155,174,184,195,233,338`.

## 5. Explicit non-findings

- **No `--json`, `--format` or `--quiet`:** JSON is already the default, and the flags would add surface without fixing anything.
- **Key style:** every captured key is camelCase; the problem is values, not keys.
- **`inbox` "compact" output:** `[]` is just an empty array under the normal pretty printer.
- **Always-present nulls** (`claude`, `opencode`, unknown tokens): consistent, and they match "unknown is not zero".
- **JSON on stdout with a non-zero `--wait` exit:** correct, because it is a result.
- **Pin two-tier error:** self-consistent. The message is one line, `requiredVersion` is validated (`project.ts:125`), paths are stripped of control characters (`project.ts:38`), and the first line is tested.
- **`nextCursor` with no CLI flag:** unreachable today, since `maxRuns` and the page limit are both 20. It only matters if that default rises.
- **Ordering:** tasks and messages are sorted, lanes follow config order, and age fields are intentionally time-varying.
- **Absolute paths, PIDs and session IDs:** acceptable for a local single-user tool. The `status` notices issue is F4.
- **Agent text in board output:** JSON-encoded, and `agents prompt` labels it as data.
- **`--project` anywhere in argv:** harmless, since option values cannot start with `--`.
