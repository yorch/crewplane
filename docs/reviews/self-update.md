# Self-update adversarial review

The operator requested an adversarial review by the Claude CLI with the exact `opus` model, read-only and scoped to `src/update.ts`, `src/cli.ts`, `install.sh`, the new tests and the changed documentation.

The review inspected the implementation and probed behaviour without running the suite or modifying files. It reported 31 findings and a verified-correct list. All findings were dispositioned; corrections below are covered by the source tests, the installer suite and the compiled acceptance unless a limitation says otherwise.

## Residual limits

- Supervisor registration is best effort and PID-based. A reused PID postpones automatic replacement; a supervisor that starts between registration and the final re-check is a narrow, documented race. Running processes keep their old binary, but their later CLI children see the new file.
- Release metadata and checksums are unauthenticated beyond TLS and the published GitHub release; signing and notarization remain open.
- Verification evidence uses a local release server and locally compiled payloads. No live published-release upgrade has been observed.
- Linux assets are glibc builds; musl/Alpine is unverified. Windows is unsupported. Downgrades require reinstalling a pinned tag with automatic updates disabled.
