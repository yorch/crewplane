# Architecture decisions

- **ADR 001 — Extract before redesign.** Retain audited file-store and scheduling/lifecycle behavior, regression fixtures and MIT provenance. SQLite is deferred so a storage migration cannot obscure extraction failures.
- **ADR 002 — Bun distribution.** Bun 1.4.1 is pinned; application CLI/runtime uses Bun and compiles with embedded static assets. Development uses strict TypeScript 7.0.2, Biome 2.6.6 and Vitest 5.1.0; Vitest runs on Node 26.11.1. Compiled operation requires neither runtime installation. Registry engine metadata was checked before pinning; native compiled scenarios provide runtime evidence. Official references: https://bun.sh/docs/compiler/executables and https://vitest.dev/guide/ .
- **ADR 003 — Project policy is explicit.** Configurable roles and committed task-document paths replace Relay ownership assumptions. Project identity uses canonical Git common directory and primary worktree discovery. Plan import is optional display data, never authorization.
- **ADR 004 — Separate observation from control.** Dashboard, supervisor and independent watchdog share services/projections. Dashboard inspection cannot start execution. Watchdog remains notice-only. Queued controls and persisted task reports are distinct from observed processes.
- **ADR 005 — External harnesses remain external.** Preserve Codex and restrictive no-tools pi protocols and add Claude Code and OpenCode adapters with explicit capabilities and synthetic stream/lifecycle fixtures. Claude/OpenCode evidence is limited to locally probed CLI protocols (2.1.319 and 2.2.5); no general provider/version compatibility is claimed. No harness authentication, browser binary or credentials are bundled, and Claude permission bypass remains unavailable.
- **ADR 006 — Explicit portable acceptance.** Native macOS/Linux binaries must run synthetic workflows with Node/Bun absent from the child's PATH, isolated worktrees, exact review, corrections, linear integration, private evidence, stop and crash recovery. Windows, signing/notarization, auto-update and global multi-project management are follow-ups.
