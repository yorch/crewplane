# Architecture decisions

- **ADR 001 — Extract before redesign.** Retain audited file-store and scheduling/lifecycle behavior, regression fixtures and MIT provenance. SQLite is deferred so a storage migration cannot obscure extraction failures.
- **ADR 002 — Bun distribution.** Bun 1.4.1 is pinned; application CLI/runtime uses Bun and compiles with embedded static assets. Development uses strict TypeScript 7.0.2, Biome 2.6.6 and Vitest 5.1.0; Vitest runs on Node 26.11.1. Compiled operation requires neither runtime installation. Registry engine metadata was checked before pinning; native compiled scenarios provide runtime evidence. Official references: https://bun.sh/docs/compiler/executables and https://vitest.dev/guide/ .
- **ADR 003 — Project policy is explicit.** Configurable roles and committed task-document paths replace Relay ownership assumptions. Project identity uses canonical Git common directory and primary worktree discovery. Plan import is optional display data, never authorization.
- **ADR 004 — Separate observation from control.** Dashboard, supervisor and independent watchdog share services/projections. Dashboard inspection cannot start execution. Watchdog remains notice-only. Queued controls and persisted task reports are distinct from observed processes.
- **ADR 005 — External harnesses remain external.** Preserve Codex and restrictive no-tools pi protocols and add Claude Code and OpenCode adapters with explicit capabilities and synthetic stream/lifecycle fixtures. Claude/OpenCode evidence is limited to locally probed CLI protocols (2.1.319 and 2.2.5); no general provider/version compatibility is claimed. No harness authentication, browser binary or credentials are bundled, and Claude permission bypass remains unavailable.
- **ADR 006 — Explicit portable acceptance.** Native macOS/Linux binaries must run synthetic workflows with Node/Bun absent from the child's PATH, isolated worktrees, exact review, corrections, linear integration, private evidence, stop and crash recovery. Windows, signing/notarization, auto-update and global multi-project management are follow-ups; auto-update is delivered by ADR 007.
- **ADR 007 — Verified self-update, never state mutation.** Release-marked binaries may update themselves, but only through the published release contract: one platform asset plus its `.sha256`. An update requires a release-marked compiled binary, a newer valid semver tag, an `https` release source (loopback allowed for tests), a matching SHA-256, the platform executable header, and a staged binary that actually runs and reports the released version, all before an atomic rename inside the install directory. Local builds are not release-marked and report `unsupported`; there is no downgrade and no signature check, so integrity comes from TLS plus the published release contents. Compile-time dotenv and `bunfig` autoload are disabled so a cloned repository cannot redirect the updater. Automatic checks are opt-out, at most once per interval (default 24 hours), started detached with a filtered environment and a neutral working directory so a foreground command never waits, recorded in a per-user cache keyed by target, and skipped for `start`, `dashboard`, `watchdog`, `monitor` and while any supervisor registration is live; the guard is re-checked immediately before the rename. Registration is best effort and PID-based. `crewplane update` stays explicit, works outside a project, prints a JSON outcome even on failure, refuses while a supervisor is registered unless `--force` is given, and is the only path that sees caller credentials. The updater never reads or writes project state, holds, budgets, leases or queued controls, and a running process keeps the binary it started with. Signing/notarization, Windows and sticky pins remain open.

## Native project integration instead of per-repository adapters

Decision: put reusable exact-version enforcement and full per-agent prompt composition in project policy v2. Projects own configuration/instructions/tasks and invoke Crewplane directly. Use a new policy version so old binaries fail closed; do not rely on older parsers rejecting unknown optional fields. Keep explicit global installation/recovery commands outside project pin enforcement and suppress background replacement for pinned project commands. Bound and canonically contain prompt files, including symlink targets. Preserve v1 compatibility and existing store schemas. Temporary product-specific migration warnings belong in that project's operating docs. No dependency or runtime wrapper is required.
